# ROADMAP.md — Дорожная карта

Продукт развивается по чётким версиям, а не по расплывчатым «этапам». Каждая
версия — самостоятельно ценный релиз, не требующий следующей версии, чтобы
приносить пользу семьям. Бизнес-модель и то, как это всё финансируется, —
[PRODUCT.md](PRODUCT.md) §11. Технические задачи, не привязанные к
конкретной версии (наведение порядка, инфраструктура), — [BACKLOG.md](BACKLOG.md).

## V1.5 — Offline-first помощник (текущий релиз)

**Цель:** максимально полезное и живое приложение без единого требования к
серверу — родитель получает всю ценность продукта даже без сети.

- **Полностью офлайн-first фронтенд.** Next.js App Router + PWA (Serwist):
  весь UI, весь контент и весь пользовательский ввод работают без сети.
  Пользовательские данные (дневник, прогресс) пишутся в LocalStorage через
  `useSyncExternalStore` за контрактами `IDiaryRepository` /
  `IProgressRepository` (Repository Pattern, см. [ARCHITECTURE.md](ARCHITECTURE.md) §5,
  [DATABASE.md](DATABASE.md) §8) — так UI уже сегодня не знает, что источник
  данных не Supabase.
- **430+ единиц проверенного контента** в `entities/*/mock`, без единого
  хардкода текста (i18n ru/kk на каждое поле): 100 игр, 100 фактов
  («А вы знали?»), 100 советов дня, 50 идей спокойных моментов, 29 возрастных
  норм, 16 статей базы знаний, 6 тематических чек-листов (31 пункт). См.
  разбивку и источники доказательности в [CONTENT.md](CONTENT.md).
- **AI-Помощник на детерминированных моках.** `POST /api/ai-chat` — 8
  быстрых вопросов × 2 языка, emergency-фильтр по ключевым словам, Guardrails
  против диагнозов/назначений — без единого вызова к внешней LLM. Полная
  спецификация мок-движка и того, что переходит в V2.0 без изменений
  контракта, — [AI_COMPANION.md](AI_COMPANION.md).
- **Локальный дневник развития и прогресс** (`/profile/diary`) — заметки
  родителя (слово/жест/игра/сон/поведение/наблюдение) и отметки о
  выполненных активностях, обе сущности уже спроектированы под будущую
  Supabase-таблицу «один в один» (см. `diary_entries`, `completed_activities`
  в [DATABASE.md](DATABASE.md)).
- Реальная авторизация email + пароль через Supabase Auth (сессии, PWA
  session persistence) — единственная часть V1.5, которая уже касается
  бэкенда, поскольку личный кабинет не может быть полностью офлайн.

**Готово (контрольный список):** см. критерии приёмки в [REQUIREMENTS.md](REQUIREMENTS.md) §4 и §6 — оба выполнены.

## V2.0 — Supabase-бэкенд

**Цель:** данные родителя (дети, дневник, прогресс) синхронизируются между
устройствами, AI отвечает по-настоящему, авторизация становится удобнее для
телефонного рынка Казахстана — без изменения ни одного экрана фронтенда.

- **Auth: телефон + OTP.** Добавляется вход по номеру телефона с
  одноразовым кодом (SMS OTP через Supabase Auth) как основной способ входа
  для казахстанской аудитории, email+пароль остаётся резервным. Гостевой
  режим просмотра mock-контента сохраняется.
- **PostgreSQL с нашими RLS.** Применение миграции
  [`supabase/migrations/20260717000000_init_schema.sql`](../app/supabase/migrations/20260717000000_init_schema.sql):
  `profiles`, `children`, `diary_entries`, `completed_activities` — Row Level
  Security включён на всех таблицах, доступ строго по `auth.uid()`, см.
  [DATABASE.md](DATABASE.md) §7. Родительский контент (статьи, нормы,
  чек-листы, игры, факты, советы, спокойные моменты) мигрирует из mock в
  собственные content-таблицы (задел — [DATABASE.md](DATABASE.md) §4).
- **Repository Pattern → реальная реализация.** `LocalStorageDiaryRepository`
  и `LocalStorageProgressRepository` (`app/src/entities/*/model/local-storage-repository.ts`)
  заменяются на `SupabaseDiaryRepository` / `SupabaseProgressRepository`,
  реализующие те же интерфейсы `IDiaryRepository` / `IProgressRepository` —
  без изменений в хуках/компонентах-потребителях.
- **Edge Functions для настоящего ИИ.** `POST /api/ai-chat` проксирует на
  Supabase Edge Function с системным промптом безопасности, Red Flags
  остаются pre-processing шагом до модели (не частью промпта). Полная
  спецификация системного промпта уже зафиксирована заранее в
  [AI_COMPANION.md](AI_COMPANION.md) §7, чтобы переход не требовал
  повторного продумывания правил безопасности.
- Офлайн-first не исчезает: мутации, сделанные без сети, копятся в очереди и
  синхронизируются по восстановлении соединения (FIFO), см.
  [DATABASE.md](DATABASE.md) §8.4.

## V3.0 — Нативные платформы

**Цель:** приложение, установленное из Google Play / App Store, с той же
кодовой базой, что и веб-PWA.

- **Обёртка через Capacitor.js.** PWA-фундамент с V1.5 спроектирован именно
  под это: никаких browser-only API без graceful fallback (см.
  [ARCHITECTURE.md](ARCHITECTURE.md) §7). Один и тот же Next.js-фронтенд
  собирается в нативный WebView-контейнер без переписывания UI.
- **Нативная сборка Android и iOS** через Capacitor CLI, нативные иконки,
  splash screen, настройка прав доступа под каждую платформу.
- **Нативные Push-уведомления** через FCM (Android) / APNs (iOS) —
  напоминания о невыполненных чек-листах, новом контенте дня, ответах
  Помощника. Веб-Push (Web Push API) как промежуточный шаг возможен раньше,
  но нативный — обязателен для V3.0.
- **Публикация в Google Play и App Store**: карточки магазинов, скриншоты,
  описание, прохождение модерации (в т.ч. подтверждение немедицинского
  статуса приложения — см. [SAFETY.md](SAFETY.md) §1).

## V4.0 — Бизнес-экосистема

**Цель:** из приложения-помощника — в экосистему, которая физически
соединяет родителя со специалистами и врачами, оставаясь бесплатной для
семьи (модель монетизации — [PRODUCT.md](PRODUCT.md) §11).

- **Каталог логопедов и детских центров Казахстана.** Верифицированный
  список специалистов (логопеды, детские психологи, коррекционные центры) по
  городам РК, с контактами и (в перспективе) записью на приём —
  `entities/specialist`, `features/specialists-catalog` (задел в
  [ARCHITECTURE.md](ARCHITECTURE.md) §9). B2B-аккаунты для центров — часть
  бизнес-модели, не платный доступ для родителей.
- **Экспорт дневника в PDF для очного приёма врача.** Заметки из
  `/profile/diary` (уже структурированы по категории и дате в
  `diary_entries`) собираются в компактный PDF-отчёт, который родитель может
  показать педиатру/логопеду на приёме — практическое применение данных,
  которые родитель и так уже ведёт, без дополнительного ввода.
- Видео-контент (уроки, короткие вебинары специалистов).
- Админ-панель для управления контентом, каталогом специалистов и B2B-аккаунтами.

## Принципы приоритизации

1. Безопасность и доверие пользователей — выше скорости фич.
2. Мультиязычность (ru/kk, задел на en) и mobile-first — не переносятся «на
   потом», действуют с V1.5.
3. Каждая новая версия — без ломающих изменений в архитектуре предыдущей
   (см. [ARCHITECTURE.md](ARCHITECTURE.md)); Repository Pattern существует
   именно для того, чтобы переход V1.5 → V2.0 не потребовал переписывания UI.
4. Продукт остаётся бесплатным для родителей на любой версии — монетизация
   всегда решается на стороне B2B/грантов/донатов, никогда за счёт платного
   доступа семьи к базовой функциональности (см. [PRODUCT.md](PRODUCT.md) §11).
