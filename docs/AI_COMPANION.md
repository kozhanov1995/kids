# AI_COMPANION.md — «Помощник»: архитектура V1.5

Этот документ описывает конкретную реализацию AI-чата ("Помощник") в кодовой
базе на этапе V1.5 (детерминированный mock-движок). Он дополняет
[AI.md](AI.md) (продуктовые принципы и тон) и [SAFETY.md](SAFETY.md)
(правила безопасности) — не дублирует их, а фиксирует, как именно они
реализованы в коде сегодня и что должно перейти в V2 (реальный LLM через
Supabase Edge Functions).

## 1. Контракт контекста

Фронтенд перед каждым запросом автоматически собирает `AssistantContext`
(`src/features/ai-chat/model/types.ts`):

```typescript
export interface AssistantContext {
  childName?: string;
  childAgeMonths?: number;
  currentLocale: 'ru' | 'kk';
  recentDiaryCategories: string[];
}
```

Источники полей (см. `ChatWindow`, `src/features/ai-chat/ui/chat-window.tsx`):

- `childName`, `childAgeMonths` — из `mockChildren[0]` (в V2 — из профиля
  ребёнка в Supabase), возраст переводится в месяцы через
  `getAgeInMonths()`.
- `currentLocale` — из `useLocale()` (next-intl), всегда `'ru' | 'kk'`.
- `recentDiaryCategories` — категории последних 5 записей локального
  дневника (`useDiary`, LocalStorage), без дублей. Используется, чтобы
  ответ мог мягко показать «вижу, вы уже это отмечали», не более того —
  движок не меняет структуру или guardrails ответа на основе дневника.

Контекст не содержит и не должен содержать: диагнозов, названий лекарств,
формулировок «отставание», «норма/не норма» — эти категории целиком
исключены из модели данных.

## 2. Быстрые вопросы (`QuickQuestion`)

```typescript
export type QuickQuestion = {
  id: QuickQuestionId;   // "noSpeech" | "noNameResponse" | ... (8 значений)
  icon: LucideIcon;
  textKey: string;       // короткая подпись на карточке (i18n-ключ)
  promptKey: string;     // полный текст вопроса, отправляемый ассистенту
};
```

Список из 8 вопросов зафиксирован в
`src/features/ai-chat/model/quick-questions.ts` и не меняется без ревью
контента — `id` каждого вопроса одновременно:

1. ключ для детерминированного поиска готового ответа в mock-движке;
2. значение, которое передаётся в query-параметре `?q=` при переходе с
   Быстрых Действий Главной страницы (`/ai-chat?q=noSpeech`).

## 3. Роутинг `?q=` (автоотправка)

`ChatWindow` читает `searchParams.get("q")` один раз при монтировании
(`autoSentRef`, чтобы не отправить дважды при перерендере):

- если значение совпадает с одним из 8 `QuickQuestionId` — вызывается
  `handleQuickQuestion(id)`: в чат подставляется локализованный
  `promptKey`-текст как сообщение пользователя, а в API уходит
  `questionId`, что гарантирует точный структурированный ответ вместо
  угадывания по ключевым словам;
- если значение — произвольный текст (обратная совместимость со старыми
  ссылками) — уходит как обычное сообщение, без `questionId`.

## 4. Мок-движок ответов (`mock-assistant.ts`)

`src/features/ai-chat/api/mock-assistant.ts` экспортирует один вход —
`getAssistantReply({ message, questionId?, context })`:

1. **Emergency-фильтр** — по ключевым словам (`не дыш`, `судорог`,
   `потерял сознан`, `тыныс алмай` и т.п.) сразу возвращает жёсткий ответ
   «звоните 103», минуя остальную логику. Это отдельный, самый
   приоритетный путь — Red Flags описаны отдельно в разделе 6.
2. **Прямое совпадение по `questionId`** — если передан (из карточки или
   `?q=`), сразу берётся соответствующий builder.
3. **Fallback по ключевым словам** — если `questionId` не передан
   (пользователь напечатал текст сам), тот же набор из 8 тем определяется
   по ключевым словам на двух языках.
4. **Generic fallback** — если ничего не подошло, возвращается общая
   поддерживающая фраза с предложением выбрать один из быстрых вопросов.

Каждый из 16 ответов (8 вопросов × 2 языка) — чистая функция
`(ctx: { subject, ageLabel, diaryHint }) => string`, строго в 4 блока:

```
{Эмпатия и валидация чувств родителя}

### {Заголовок блока объяснения}
{Простое объяснение процессов развития для возраста ребёнка (ageLabel)}

### {Заголовок блока игры}
{Конкретная микро-игра на 5 минут из подручных материалов}

### {Заголовок блока безопасности}
{Мягкий маркер: когда очно показаться специалисту}
```

`ageLabel` вычисляется чистой функцией `formatAgeLabel()`
(`src/features/ai-chat/lib/format-age-label.ts`) — без хуков next-intl,
чтобы её можно было переиспользовать и на сервере/в Edge Function в V2.
Имя ребёнка подставляется только в позиции подлежащего (именительный
падеж), чтобы не ломать русскую морфологию при склонении.

Ответ рендерится в чате через `MarkdownLite`
(`src/features/ai-chat/ui/markdown-lite.tsx`) — это не полноценный
Markdown-парсер, а лёгкий рендер ровно того подмножества, которое
используется в 16 ответах: `### ` заголовки, `**bold**`, списки `- ` и
абзацы. Осознанное решение не тянуть зависимость (`react-markdown` и т.п.)
ради полностью контролируемого нами контента.

## 5. Guardrails (проверка соответствия)

Все 16 ответов и весь fallback-контент проверены на:

- **Запрет диагнозов** — нигде не используются слова «ЗРР», «аутизм»,
  «задержка развития» как ярлык, «диагноз».
  Смотрите docs/CONTENT_RULES.md за общим списком.
- **Запрет назначений** — ни разу не встречается «нужно давать», «пропить»,
  «ноотроп», «дозировка», название лекарств.
- **Обязательная поддерживающая формулировка** в блоке безопасности каждого
  ответа: «можно мягко понаблюдать», «оптимальным шагом будет очная
  консультация специалиста» (педиатра/логопеда/детского психолога — в
  зависимости от темы).
- Блок безопасности **всегда** предлагает специалиста как следующий шаг
  «для спокойствия», никогда не констатирует, что что-то не так.

## 6. Red Flags (экстренные ситуации)

Red Flags обрабатываются `EMERGENCY_KEYWORDS` в `mock-assistant.ts` —
отдельный, приоритетный перед всей остальной логикой путь. Он не пытается
быть «умным» (никакого контекста, никакого форматирования по 4 блокам) —
единственная задача: как можно быстрее вывести пользователя из чата к
реальной помощи:

> «Это похоже на ситуацию, которая требует немедленной очной медицинской
> помощи. Пожалуйста, не ждите ответа в чате — звоните 103 или обратитесь
> в скорую помощь прямо сейчас.»

Дополнительно в интерфейсе есть постоянно видимая кнопка «Это экстренная
ситуация?» (не зависящая от текста сообщения) — открывает диалог с тем же
явным призывом звонить 103, на случай если родитель не может точно
сформулировать сообщение.

**V2 note**: при переходе на реальную модель Red Flags должны остаться
отдельным pre-processing шагом (regex/классификатор) ДО обращения к LLM,
а не частью системного промпта — так у нас есть гарантия, что экстренный
путь никогда не зависит от качества генерации модели.

## 7. Системный промпт для V2 (Supabase Edge Function)

Когда мок-движок будет заменён вызовом реальной модели, `POST
/api/ai-chat` сохраняет тот же контракт запроса/ответа
(`{ message, locale, questionId?, context }` → `{ reply }`), меняется
только его тело — вместо `getAssistantReply()` вызывается Edge Function.
Системный промпт для этой функции должен содержать:

```
Ты — Помощник в приложении Kids Growth для родителей детей 0–7 лет
в Казахстане. Ты не врач и не ставишь диагнозы.

Контекст текущего разговора:
- Имя ребёнка: {childName}
- Возраст ребёнка: {childAgeMonths} месяцев
- Язык ответа: {currentLocale} (всегда отвечай на этом языке)
- Недавние темы в дневнике родителя: {recentDiaryCategories}

Правила (обязательны для каждого ответа):
1. Никогда не ставь диагноз и не используй ярлыки диагнозов
   ("ЗРР", "аутизм", "задержка развития" и т.п.).
2. Никогда не назначай лечение, препараты, ноотропы или дозировки.
3. Каждый ответ строй в 4 блока: эмпатия → простое объяснение процессов
   развития для указанного возраста → одна конкретная микро-игра на 5 минут
   из бытовых материалов → мягкий маркер "когда стоит показаться
   специалисту" (используй только фразы вроде "можно мягко понаблюдать",
   "оптимальным шагом будет очная консультация специалиста").
4. Отвечай в Markdown, короткими абзацами, подходящими для мобильного
   экрана.
5. Если сообщение похоже на экстренную ситуацию (потеря сознания,
   остановка дыхания, судороги, высокая температура) — НЕ обрабатывай его
   обычным образом, а сразу верни фиксированный ответ с призывом звонить 103.
6. Опирайся только на контент базы знаний приложения и общепризнанные
   международные рекомендации (WHO, CDC, AAP) — никогда не выдумывай факты
   или источники.
```

Пост-обработка ответа (middleware-валидатор, см. AI.md §4) должна остаться
и в V2 как последний рубеж — проверка на запрещённые паттерны перед
показом пользователю, даже если модель обучена следовать системному
промпту.
