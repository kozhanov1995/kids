# I18N.md — Мультиязычность

## 1. Поддерживаемые языки

| Код | Язык | Статус |
|---|---|---|
| `ru` | Русский | Основной, дефолтный |
| `kk` | Қазақша | Полная поддержка с первого дня |
| `en` | English | Зарезервировано, не переводится на Этапе 1, но архитектура готова |

## 2. Технология

- **next-intl** — интеграция с Next.js App Router, локаль в сегменте пути: `/ru/...`, `/kk/...`.
- `middleware.ts` определяет локаль по cookie `NEXT_LOCALE`, затем по заголовку `Accept-Language`, иначе — дефолт `ru`.
- Файлы переводов — `shared/i18n/messages/{locale}.json`, структурированы по неймспейсам, соответствующим фичам/страницам (`common`, `nav`, `home`, `knowledge`, `milestones`, `checklists`, `games`, `aiChat`, `profile`, `settings`, `auth`).

## 3. Правила

1. **Никогда не хардкодить пользовательский текст** в компонентах — только через `useTranslations('namespace')`.
2. Ключи именуются по смыслу, не по месту использования (`checklistProgressLabel`, а не `text3`).
3. Плюрализация и интерполяция — через ICU message format, поддерживаемый next-intl (`{count, plural, ...}`).
4. Даты, числа — через `next-intl` форматтеры (`useFormatter`), с учётом локали (казахская локаль использует те же числовые форматы, что и русская, но собственные названия месяцев).
5. Новые тексты добавляются одновременно в `ru.json` и `kk.json` — PR с отсутствующим переводом считается неполным. Отсутствие ключа в `kk.json` не должно приводить к падению сборки — только к предупреждению (fallback на `ru`).

## 4. Структура файла переводов (пример)

```json
{
  "nav": {
    "home": "Главная",
    "knowledge": "База знаний",
    "milestones": "Нормы",
    "checklists": "Чек-листы",
    "games": "Игры",
    "aiChat": "AI-помощник",
    "profile": "Профиль",
    "settings": "Настройки"
  }
}
```

Казахский эквивалент хранится в `kk.json` с идентичной структурой ключей.

## 5. Переключение языка

- Доступно в Настройках (`features/settings`) и в шапке приложения (иконка глобуса).
- Смена языка обновляет URL-локаль (редирект на `/kk/...` или `/ru/...`) и сохраняет выбор в `profiles.locale` (для авторизованных) и в cookie (для гостей).

## 6. Готовность к English

- Все компоненты используют только ключи из `messages`, поэтому добавление `en.json` не требует изменений в коде компонентов — только перевод файла и добавление `en` в список `locales` в конфиге i18n.
- UI не завязан на длину текста конкретного языка (используются flex-контейнеры, а не фиксированная ширина под текст).

## 7. Локализация контента (База знаний, Нормы, Игры, Чек-листы)

- Контентные mock-данные хранят поля с суффиксом локали или вложенный объект `{ ru: {...}, kk: {...} }` — см. [CONTENT.md](CONTENT.md).
- В будущей БД (см. [DATABASE.md](DATABASE.md)) поле `locale` в каждой контентной таблице либо отдельная таблица переводов — решение принимается на Этапе 2 в зависимости от объёма контента.

## 8. Направление письма

- Оба языка (ru, kk) — LTR, RTL не требуется. Компоненты не должны жёстко полагаться на LTR в критичных местах (использовать logical properties Tailwind — `ms-*`/`me-*` вместо `ml-*`/`mr-*` там, где это дёшево), чтобы не создавать долг на будущее.

## 9. V1 — новые неймспейсы

Добавлены неймспейсы `facts`, `calm`, `diary`, а также расширения `home` (`todayForYou`, `quickActions`, заголовки новых блоков) и `games` (новые цели `attention`/`gestures`/`imitation`/`calm`, раздел `dailyTitle`/`gentleReminder`). Все ключи присутствуют в `ru.json` и `kk.json` в одинаковой структуре.

Перед добавлением новых текстов удобно проверять структурный паритет файлов:

```bash
node -e "
const ru = require('./src/shared/i18n/messages/ru.json');
const kk = require('./src/shared/i18n/messages/kk.json');
function keys(o, p = '') { return Object.entries(o).flatMap(([k, v]) => typeof v === 'object' && !Array.isArray(v) ? keys(v, p + k + '.') : [p + k]); }
const a = new Set(keys(ru)), b = new Set(keys(kk));
console.log('missing in kk:', [...a].filter(k => !b.has(k)));
console.log('missing in ru:', [...b].filter(k => !a.has(k)));
"
```
