# REQUIREMENTS.md — Требования

## 1. Функциональные требования (Этап 1)

### 1.1 Авторизация
- Регистрация / вход по email + паролю (Supabase Auth).
- Вход через магическую ссылку (magic link) — опционально, задел на будущее.
- Восстановление пароля.
- Гостевой режим для просмотра mock-контента без регистрации (кроме персональных разделов: профиль, чат-история).
- Сессия сохраняется (Supabase session persistence), работает офлайн-friendly (PWA).

### 1.2 Профиль
- Профиль родителя: имя, email, язык интерфейса, аватар.
- Профиль ребёнка: имя, дата рождения, пол (опционально), фото (опционально).
- Поддержка нескольких детей в семье (заложено в модели данных, UI может быть упрощён на Этапе 1).
- Автоматический расчёт возраста ребёнка (месяцы/годы) для персонализации норм и чек-листов.

### 1.3 Главная (Дашборд)
- Приветствие, краткая сводка по ребёнку (текущий возраст, ближайшие вехи).
- Быстрые ссылки на разделы: База знаний, Возрастные нормы, Чек-листы, Игры, AI Chat.
- Рекомендованный контент дня/недели (mock-подборка).

### 1.4 База знаний
- Каталог статей по категориям (сон, питание, здоровье, развитие, психология, безопасность и т.д.).
- Поиск и фильтрация по категории и возрасту.
- Карточка статьи: заголовок, обложка, время чтения, теги, содержимое.
- Дисклеймер об информационном характере контента.

### 1.5 Возрастные нормы
- Разделение по сферам развития: физическое, речевое, когнитивное, социально-эмоциональное, бытовые навыки.
- Возрастные диапазоны (0-3 мес, 3-6, 6-9, 9-12, 1-1.5 года, ... до 7 лет).
- Персонализация: подсветка норм, актуальных для текущего возраста ребёнка пользователя.
- Явный дисклеймер: нормы — ориентир, а не диагностика.

### 1.6 Чек-листы
- Наборы чек-листов по темам (например: «Подготовка к первому прикорму», «Безопасность дома», «Готовность к детскому саду», «Вакцинация — что уточнить у педиатра»).
- Возможность отмечать пункты выполненными (локально на Этапе 1, синхронизация с Supabase в будущем).
- Прогресс-бар выполнения по чек-листу.

### 1.7 Игры
- Каталог развивающих игр/активностей с фильтрами по возрасту и цели развития (моторика, речь, логика, творчество).
- Карточка игры: описание, что развивает, что понадобится, длительность.
- Избранное (заложено на будущее).

### 1.8 AI Chat
- Чат-интерфейс с AI-помощником.
- Помощник отвечает спокойно, доступно, без постановки диагнозов и назначения лечения.
- Предопределённые быстрые вопросы (suggested prompts).
- Явный дисклеймер над чатом и в системном поведении помощника (см. [AI.md](AI.md), [SAFETY.md](SAFETY.md)).
- На Этапе 1 — mock-ответы/заглушка интеграции с LLM API (архитектура готова для реального подключения).

### 1.9 Профиль пользователя и Настройки
- Просмотр/редактирование данных родителя и ребёнка.
- Настройки: язык (ru/kk), тема (light/dark/system), уведомления (заглушка), приватность, выход из аккаунта.
- Ссылки на политику конфиденциальности и условия использования.

## 2. Нефункциональные требования

### 2.1 Производительность
- Core Web Vitals: LCP < 2.5s, CLS < 0.1, INP < 200ms на мобильных сетях 4G.
- Ленивая загрузка изображений и некритичных компонентов.
- Разделение бандлов по маршрутам (App Router автоматически поддерживает code splitting).

### 2.2 Mobile First
- Проектирование от 360px ширины экрана вверх.
- Нижняя навигация (bottom navigation) как основной способ перемещения на мобильных.
- Touch-friendly интерактивные элементы (мин. 44x44px).

### 2.3 PWA / готовность к WebView
- Манифест (manifest.json), иконки, service worker с офлайн-кэшированием статики.
- Установка на домашний экран (Add to Home Screen).
- Никаких решений, несовместимых с последующей упаковкой в Android/iOS WebView (никаких browser-only API без graceful fallback).

### 2.4 Мультиязычность
- Полная поддержка русского и казахского языков с первого дня.
- Архитектура словарей допускает добавление английского без рефакторинга.
- Никакого хардкода текста в компонентах — весь UI-текст через i18n-ключи.

### 2.5 Доступность (a11y)
- Семантическая разметка, ARIA-атрибуты для интерактивных компонентов.
- Контрастность текста согласно WCAG AA.
- Поддержка навигации с клавиатуры.

### 2.6 Безопасность и приватность
- Валидация всех форм на клиенте (Zod) и предполагается на сервере (Supabase RLS policies).
- Минимизация сбора персональных/чувствительных данных.
- См. [SAFETY.md](SAFETY.md).

### 2.7 Качество кода
- TypeScript strict mode, без `any` без явного обоснования.
- ESLint + Prettier без ошибок и предупреждений при сборке.
- Feature-Based Architecture, SOLID/DRY/KISS.
- Компоненты и хуки покрываемы тестами (инфраструктура заложена, тесты — по мере роста проекта).

### 2.8 Масштабируемость
- Возможность добавления новых фич без изменения существующих модулей (см. [ARCHITECTURE.md](ARCHITECTURE.md)).
- Готовность к будущим возможностям: push-уведомления, AI-планы развития, каталог специалистов, видео, дневник развития, семейный кабинет, несколько детей, подписки, админ-панель.
- Пользовательские данные, которые в будущем переедут в Supabase (дневник, прогресс выполненных активностей), обязаны идти через интерфейсы Repository Pattern — `IDiaryRepository`, `IProgressRepository` (`entities/diary-entry/model/repository.ts`, `entities/progress/model/repository.ts`) — а не напрямую через `localStorage`/`fetch` из компонентов. Это гарантирует, что переход на реальный бэкенд (см. [DATABASE.md](DATABASE.md), [ROADMAP.md](ROADMAP.md) V2.0) не потребует переписывания UI-кода — только новую реализацию интерфейса.

## 3. Ограничения (Constraints)

- Первый релиз — mock-данные для контента (без реального бэкенда для контента), но с реальной интеграцией Supabase Auth.
- Целевые языки интерфейса: ru (по умолчанию), kk.
- Целевые платформы Этапа 1: мобильный веб (PWA) и десктоп-веб как адаптивный fallback.

## 5. Функциональные требования V1 (ежедневная польза)

Этап V1 добавляет к Этапу 1 набор функций, превращающих приложение из справочника в персонального помощника с ежедневным поводом открыть его.

### 5.1 Today screen («Сегодня для вашего ребёнка»)
- Главная страница перестаёт быть каталогом разделов и становится персональной лентой.
- Приветствие адаптируется к времени суток и имени родителя; при наличии профиля ребёнка показывается его имя и точный возраст (годы + месяцы).
- Лента состоит из блоков: «Сегодня рекомендуем», «Быстрые действия», «Продолжить» (если есть незавершённый чек-лист), «5 минут вместе», «Полезно сегодня» (совет дня, см. 5.3.1), «А вы знали?», «Спокойный момент», подборка статей недели, блок эмоциональной поддержки.

### 5.2 Daily Recommendations
- Модуль `features/daily-recommendations` детерминированно выбирает «пункт дня» (игра, факт, статья, чек-лист, спокойный момент) на основе календарной даты — без бэкенда, без случайности между перезагрузками в один и тот же день.
- Быстрые действия — до шести сценариев («ребёнок не говорит», «не реагирует на имя», «много смотрит экран», «плохой сон», «подобрать игру», «задать вопрос ИИ»), ведущие либо в AI-чат с предзаполненным вопросом, либо в раздел игр.

### 5.3 Факты («А вы знали?»)
- Отдельный раздел `/knowledge/facts`, доступный из базы знаний.
- Факты короткие (≈30 секунд чтения), с иллюстрацией, категорией и возрастным диапазоном; фильтрация по категории.

### 5.3.1 Советы дня («Полезно сегодня»)
- Сущность `Tip` (`entities/tip`) — короткий, конкретный совет-действие для родителя (в отличие от `Fact`, который констатирует закономерность, а не советует что делать).
- Показывается на Главной в блоке «Полезно сегодня» через тот же детерминированный «пункт дня» (`daily-recommendations`), что и игра/факт/чек-лист/спокойный момент.
- Формулировки — только мягкие рекомендательные конструкции («стоит попробовать», «может помочь»), без категоричных предписаний — см. [CONTENT_RULES.md](CONTENT_RULES.md).

### 5.4 5 минут вместе
- Отдельный раздел `/games/daily` с ежедневными короткими (≤10 минут) играми на бытовые темы: речь, внимание, жесты, имитация, моторика, совместная игра, спокойствие.
- Каждая игра — с мягким советом родителю и универсальным напоминанием «Главное — не заставлять, а играть вместе».

### 5.5 Спокойные моменты
- Раздел `/calm` с идеями спокойных ритуалов: классическая музыка, колыбельные, звуки природы, белый шум, ритуал перед сном, спокойная игра.
- Этап V1 — только mock-карточки с плейсхолдер-кнопкой «Слушать позже»; реального аудио нет. Архитектура не блокирует последующее подключение аудио-источника.
- Формулировки строго придерживаются `docs/CONTENT_RULES.md` — никаких обещаний терапевтического эффекта.

### 5.6 Дневник развития (мини-версия)
- Раздел `/profile/diary`: добавление заметки (категория + текст), список заметок, блок достижений (новые слова, новые жесты, совместные игры, дни наблюдений).
- Хранение — в localStorage через `features/diary` (тот же паттерн `useSyncExternalStore`, что и прогресс чек-листов) за контрактом `IDiaryRepository` (`entities/diary-entry/model/repository.ts`), с явным расчётом на последующий перенос в Supabase (см. [DATABASE.md](DATABASE.md)). Отметки о выполненных активностях (игра/факт/статья/чек-лист/совет пройдены) — аналогичный контракт `IProgressRepository` (`entities/progress/model/repository.ts`).

### 5.7 AI Chat — быстрые вопросы
- Стартовый экран чата больше не пустой: показывает иллюстрацию помощника и до восьми быстрых вопросов на частые темы (речь, реакция на имя, жесты, экранное время, сон, совместная игра, подбор игры, подготовка к логопеду).
- Быстрые действия с Главной могут открывать чат с предзаполненным и автоматически отправленным вопросом через параметр `?q=`.
