# BACKLOG.md — Архитектурный бэклог

Технические задачи, не привязанные к конкретной продуктовой версии из
[ROADMAP.md](ROADMAP.md) — инфраструктура, качество, наблюдаемость. Порядок
внутри приоритета — рекомендованный порядок выполнения.

## High — сделать в первую очередь

1. **Агрессивное кэширование статики через Service Worker.** Расширить
   конфигурацию Serwist (`app/src/app/sw.ts`, см. [ARCHITECTURE.md](ARCHITECTURE.md) §7)
   стратегией `CacheFirst`/`StaleWhileRevalidate` для шрифтов, иллюстраций и
   контентных JSON-чанков, чтобы повторный запуск приложения был мгновенным
   даже на слабой сети — ключевое ощущение для offline-first продукта.
2. **Автоматический CI-тест на паритет ключей `ru.json`/`kk.json`.** В
   [I18N.md](I18N.md) §9 уже есть рабочий node-сниппет для сверки ключей —
   его нужно оформить как постоянный скрипт (`app/scripts/check-i18n-parity.mjs`)
   и подключить в CI (или хотя бы в `npm run lint`/pre-commit), чтобы PR с
   отсутствующим переводом падал автоматически, а не полагался на ревью
   человеком.
3. **Лёгкая аналитика (Umami или Mixpanel).** Подключить privacy-friendly
   аналитику событий (открытие Today-ленты, использование быстрых действий,
   завершение чек-листа, диалог с Помощником) — без которой продуктовые
   решения по [ROADMAP.md](ROADMAP.md) принимаются вслепую. Umami
   предпочтителен по умолчанию как self-hosted/без сбора персональных данных,
   что упрощает согласование с [SAFETY.md](SAFETY.md) §5.

## Medium — важно, но не блокирует текущий релиз

4. **Supabase CLI миграции.** Настроить `supabase/config.toml` и рабочий
   процесс `supabase migration up`/`db diff` вокруг уже существующей
   [`supabase/migrations/20260717000000_init_schema.sql`](../app/supabase/migrations/20260717000000_init_schema.sql),
   чтобы V2.0 не начиналась с ручного накатывания SQL через Studio.
5. **OTP-авторизация по номеру телефона.** Реализация части V2.0 из
   [ROADMAP.md](ROADMAP.md) — Supabase Auth phone provider, экран ввода
   номера и кода, обработка resend/rate-limit, тексты ошибок в духе
   [BRAND.md](BRAND.md) §10 (без «Invalid OTP code», по-человечески).
6. **Кэширование ответов ИИ на бэкенде.** Для повторяющихся вопросов
   (особенно 8 быстрых вопросов, см. [AI_COMPANION.md](AI_COMPANION.md) §2)
   кэшировать ответ Edge Function по `(questionId, ageRangeBucket, locale)` —
   прямая экономия токенов, напрямую поддерживающая модель окупаемости из
   [PRODUCT.md](PRODUCT.md) §11.
7. Синхронизация локального дневника/прогресса с Supabase после входа в
   аккаунт (миграция уже накопленных LocalStorage-записей при первой
   авторизации, а не их потеря).
8. Полнотекстовый поиск по базе знаний (`pg_trgm`/`tsvector`) — актуально с
   момента переноса статей из mock в Postgres.
9. Хелпер `getLocalizedField(entity, field, locale)` для контента,
   упомянутый в [CONTENT.md](CONTENT.md) §8, но фактически ещё не
   выделенный как переиспользуемая shared-утилита (сейчас доступ к
   локализованным полям продублирован по фичам).
10. Мониторинг ошибок (Sentry или аналог) — заложено как намерение в
    [SAFETY.md](SAFETY.md) §9, но не подключено технически.

## Low — полезно, можно отложить

11. **Сквозные Playwright-тесты для логики дневника** (`/profile/diary`):
    добавление записи, отображение в списке, удаление, персистентность после
    reload — единственный раздел с недоверенной пользовательским вводом
    логикой (LocalStorage read/write через `IDiaryRepository`), у которого
    пока нет автоматической проверки регрессий.
12. Визуальный regression-тест (Chromatic/Percy или снапшоты Playwright) для
    ключевых экранов — защита дизайн-системы из [BRAND.md](BRAND.md) от
    случайных отклонений при рефакторинге компонентов.
13. Bundle-анализ (`@next/bundle-analyzer`) как разовый аудит перед V3.0 —
    вес JS-бандла особенно важен внутри Capacitor WebView на бюджетных
    Android-устройствах.
14. Storybook (или аналог) для `shared/ui`/`shared/illustrations` — сейчас
    единственный способ увидеть все состояния компонента — искать его
    использование по всему приложению.
15. Скрипт валидации контента при сборке (`npm run validate:content`):
    проверка, что каждая mock-запись имеет непустые `ru`/`kk` для всех
    локализуемых полей и что текст не содержит запрещённых формулировок из
    [CONTENT_RULES.md](CONTENT_RULES.md) §1 — автоматизация текущего
    ручного чек-листа из CONTENT_RULES.md §4.
