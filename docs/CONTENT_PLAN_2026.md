- **Articles**: 16 статей на 8 категорий (в среднем 2), очень мало — почти вся категория "речь" (1 статья).
- **Facts/Tips**: ровно распределены по 8 категориям (~12–13 каждая), просто нужно кратно больше.
- **Checklists**: только 6, по одному чек-листу почти на каждую категорию, нет чек-листов на бытовые ситуации (безопасность кухни/машины/площадки/воды, приучение к горшку, детский сад — адаптация, второй ребёнок и т.д.)
- **Milestones**: единственный реальный пробел — `selfCare` не имеет записи для 3–6 месяцев (у всех остальных доменов 6 диапазонов, у selfCare — 5).
- **Calm moments**: 6 категорий по 8–9 штук, ровно, просто мало для "80–120".
- **Media**: почти нет media_assets, кроме 5 обложек фактов и 8 аудио. Расширяем точечно (см. §5).

## 3. Стратегия для "5 минут вместе" (daily_game)

`entities/game/mock/daily-games.ts` — это **курируемая выборка** ID из `mockGames` (не отдельный контент, во избежание дублирования — так спроектировано изначально, см. комментарий в файле и `docs/CONTENT.md` §9). При импорте один и тот же объект игры пишется в `content_items` дважды — как `game` и как `daily_game` (разные строки по PK `(content_type, slug)`), это нормально и predусмотрено схемой.

План: при добавлении новых игр специально проектируем много игр с `durationMinutes <= 10` и `materialsNeeded` пустым/из 1 бытового предмета — ровно то, что нужно для "выполнить сразу без подготовки". Затем расширяем `DAILY_GAME_IDS` этим пулом (старые + новые игры), доводя список до ~110–120 ID. Это даёт нужный объём "5 минут вместе" без искусственного дублирования контента другими словами.

## 4. Правила качества и безопасности (применяются ко всем батчам)

1. **Zod-схема** (`src/shared/content/schemas.ts`) — обязательный `safeParse` перед импортом (выполняет `scripts/import-content.ts` и наш `scripts/validate-content.ts`).
2. **Дубликаты/почти-дубликаты**: перед написанием каждого батча — grep существующих `title.ru` по файлам; после — скрипт проверки на точные и почти-точные совпадения slug/title (см. §6).
3. **Возрастная уместность**: диапазоны месяцев проверяются на здравый смысл (например, не предлагать ножницы 12-месячному).
4. **RU** — родной уровень редактора (это основной язык бренда), проверяется вручную по ходу написания.
5. **KK** — переводится вместе с RU. Короткие структурированные форматы (game/fact/tip/calm/checklist/milestone) — публикуются сразу (`published`), т.к. фразы короткие, типовые, легко проверяемые. **Статьи (article)** — более длинный, нюансный текст: KK-версии импортируются, но статьи из этого батча помечаются `status = review` (не `draft`, чтобы не потерять черновик, но и не `published`, чтобы не показывать непроверенный длинный KK-текст пользователям) до тех пор, пока носитель языка не подтвердит формулировки. Это соответствует брифу: "если казахский перевод генерируется неуверенно, помечай его как requiring_review вместо публикации как гарантированно корректного".
6. **Медицинская безопасность**: никаких диагнозов, категоричных "должен/обязан", тревожных формулировок — см. `docs/CONTENT_RULES.md`. `whenToSeeSpecialist` — всегда мягкая формулировка "стоит обсудить", никогда "это признак болезни".
7. **AI-факты**: никаких псевдонаучных/тревожных утверждений — только фактическая матчасть про развитие, историю, физиологию, воспитание, безопасно проверяемая на здравый смысл.

## 5. Медиа (точечно, без "картинка ради картинки")

Приоритет по брифу: Home/Daily → ключевые Games → Knowledge → Facts → Calm → empty/featured states.

План: сгенерировать ~12–18 новых обложек (`scripts/generated-images` + upload в `media_assets`) для:
- Home/Daily rail (1 иллюстрация состояния "нет активности на сегодня" / featured).
- 5–6 ключевых новых игр (по одной на самые новые категории/цели — жесты, имитация, совместная игра).
- 3–4 обложки для новых статей (по одной на самую слабую категорию — речь, эмоции).
- 2–3 обложки для новых фактов (чтобы не было "картинка ради картинки" — только там, где раздел визуально пустой).
- Не более 2–3 для Calm (остальные категории уже закрыты текстом + аудио).

Стиль — см. `docs/BRAND.md`: мягкие пастельные формы, без реалистичных лиц/детей, светлая/тёмная тема совместимость (тестируется вручную в браузере).

## 6. QA-пайплайн перед публикацией

`scripts/validate-content.ts` (новый, не меняет существующий `import-content.ts`):
1. Импортирует все mock-массивы.
2. `safeParse` каждой записи по Zod-схеме своего типа.
3. Проверка уникальности `slug` в рамках типа.
4. Проверка "почти дублей" заголовков (нормализация + сравнение по частоте общих слов ≥ 0.8 в пределах одного типа+категории/цели).
5. Проверка на отсутствие "kk" (пустая строка) / RU==KK (означает "забыли перевести").
6. Отчёт по возрастному распределению и распределению по категориям/целям на выходе.

Только после чистого прогона — `npm run import:content` (существующий скрипт, идемпотентный upsert).

Медиа: новых картинок сознательно не создавалось. Единственный тип, чья карточка реально показывает загруженную обложку вместо иллюстрации, — `Fact` (`fact-card.tsx`); у него уже есть 5 обложек, корректно привязанных к 5 разным фактам через `cover_media_id`. Добавлять новые изображения для типов, чьи карточки эту обложку никак не выводят (Article/Game/CalmMoment), означало бы тратить платную генерацию на невидимый результат — этого не делали, отметили как пункт на будущее (нужен код в карточках + admin UI для привязки обложки, которого сегодня нет).
